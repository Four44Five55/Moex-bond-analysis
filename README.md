# MOEX Analytics — анализ облигаций и акций

Веб-приложение для анализа инструментов Московской биржи (облигации и акции):
детальный анализ, поиск, фильтрация, графики исторических цен, избранное и сравнение,
а также учёт собственного портфеля — сделки, позиции по FIFO, аллокация, доходный
календарь, налоги и доходность XIRR.

## Стек

- **Backend:** Java 21, Spring Boot 3.4 (Web, Data JPA, Data Redis, Cache, Validation), PostgreSQL 16,
  Redis 7, Flyway, OkHttp, Apache POI, springdoc/OpenAPI. Тесты: JUnit 5 + Testcontainers.
- **Frontend:** React 18 + TypeScript + Vite, TanStack Query, React Router, lightweight-charts.
- **Инфраструктура:** Docker Compose (Postgres + Redis).

## Архитектура (backend, слоистая / hexagonal-lite)

```
web            REST-контроллеры v1, DTO (records), маппер, обработчик ошибок, OpenAPI
application    use-cases/фасады: InstrumentService, SyncService, CandleService,
               WatchlistService, ExportService, AccountService, TransactionService,
               PortfolioService; события (Observer)
domain         модель (Instrument→Bond/Share, Candle, WatchlistItem, Account, Transaction),
               analysis/* (доходности, дивиденды, скоринг), фильтры (Specification),
               portfolio/* (FIFO, прогноз выплат), portfolio/tax/* (стратегии НДФЛ),
               portfolio/allocation/* (измерения), portfolio/history/* (ряд стоимости, XIRR),
               порты (MarketDataProvider, CandleProvider, CorporateActionsProvider)
infrastructure адаптеры: moex/* (клиент+парсеры), persistence/* (Spring Data JPA),
               cache/* (Redis), scheduler/* (синхронизация)
```

**SOLID:** SRP (парсер/анализатор/репозиторий/контроллер раздельно), OCP (новый тип = новая стратегия),
LSP (Bond/Share ↔ Instrument), ISP (узкие порты), DIP (домен зависит от портов, реализации — в infrastructure).

**Паттерны GoF:** Strategy (парсеры/скоринг по типу, стратегии НДФЛ, измерения аллокации),
Abstract Factory / Adapter (MOEX-клиент), Factory Method (`TaxStrategyFactory`, `AllocationDimensionFactory`),
Template Method (поток загрузки MOEX, `AbstractTaxStrategy`), Builder (`PortfolioValueRequest`),
Repository + Specification (динамические фильтры), Facade (`InstrumentService`, `PortfolioService`),
Observer (`DataRefreshedEvent`), Decorator/Proxy (Spring Cache поверх портов).

**Конкурентность:** облигации и акции загружаются параллельно (`CompletableFuture` + выделенный пул),
свечи кешируются (cache-aside: PostgreSQL → MOEX), горячие ответы — в Redis; планировщик `@Scheduled`
периодически синхронизирует данные и сбрасывает кеши через событие.

### На что легко наступить

**Чтение свечей — операция записи.** `CandleService.getCandles` работает по cache-aside: недостающие
отрезки периода догружаются из MOEX и сохраняются в БД. Сервисы же помечены `@Transactional(readOnly = true)`
на уровне класса, а вложенный `@Transactional` при распространении `REQUIRED` присоединяется к внешней
транзакции и её read-only не отменяет — PostgreSQL отвергнет INSERT. Поэтому любой публичный метод,
который вызывает `CandleService`, обязан перекрыть транзакцию своим `@Transactional`: так сделано
в `InstrumentService.performance` и `PortfolioService.valueSeries`. Модульные тесты это не ловят.

**Свечи не перезапрашиваются целиком.** Хвост периода догружается **включая** последнюю сохранённую
дату: свеча текущего дня пишется незакрытой и должна перезаписаться. На таблице `candle` висит
`UNIQUE (sec_id, interval_code, ts)`, поэтому между удалением отрезка и вставкой стоит явный
`flush()` — иначе Hibernate выполнит INSERT раньше DELETE и нарушит ограничение.

## Запуск

Порты подобраны без конфликтов: backend **8090**, frontend dev **5180**, Postgres **5445**, Redis **6380**.

```bash
# 1. Инфраструктура
docker compose up -d

# 2. Backend (http://localhost:8090, Swagger UI: /swagger-ui.html)
cd backend
./gradlew bootRun        # при пустой БД выполнит стартовую синхронизацию с MOEX

# 3. Frontend (http://localhost:5180)
cd frontend
npm install
npm run dev
```

## REST API (`/api/v1`)

| Метод | Путь | Описание |
|-------|------|----------|
| GET  | `/instruments?type=BOND\|SHARE&query=&minYield=&maxDuration=&minReliability=&onlyInvestmentGrade=&sector=&page=&size=&sort=` | Список с фильтрами, пагинацией, сортировкой; для облигаций — сводка |
| GET  | `/instruments/search?query=` | Глобальный поиск по облигациям и акциям |
| GET  | `/instruments/{secId}` | Детальная карточка (для облигаций — НКД, дата оферты, текущая доходность) |
| GET  | `/instruments/{secId}/candles?interval=24&from=&to=` | Исторические свечи |
| GET  | `/instruments/{secId}/payments` | История выплат: купоны/амортизации (облигация) или дивиденды (акция) |
| GET  | `/instruments/{secId}/performance` | Доходности за 1Д/1Н/1М/1Г/YTD и 52-недельный диапазон цен |
| GET  | `/instruments/{secId}/dividend-yield` | Дивидендная доходность акции за 12 месяцев |
| GET  | `/instruments/compare?secIds=SBER,GAZP,...` | Данные для сравнения |
| POST | `/instruments/refresh` | Синхронизация с MOEX (облигации + акции) |
| GET  | `/export?type=&...фильтры` | Экспорт выборки в Excel (.xlsx) |
| GET/POST/DELETE | `/watchlist` | Анонимное избранное |

### Портфель

Все методы ниже требуют заголовок `X-Client-Id` и работают только со счетами этого клиента.

| Метод | Путь | Описание |
|-------|------|----------|
| GET/POST | `/accounts` | Список счетов, создание (брокерский или ИИС типа А/Б) |
| GET/PUT/DELETE | `/accounts/{id}` | Карточка счёта, изменение, удаление |
| GET/POST | `/accounts/{id}/transactions` | Сделки счёта, добавление покупки/продажи |
| DELETE | `/accounts/{id}/transactions/{txId}` | Удаление сделки |
| GET  | `/accounts/{id}/overview` | **Страница счёта целиком**: сводка, позиции, выплаты и налог одним ответом |
| GET  | `/accounts/{id}/positions` | Открытые позиции по FIFO: количество, средняя цена, P&L |
| GET  | `/accounts/{id}/summary` | Сводка: вложено, стоимость, P&L, комиссии, доход, налог |
| GET  | `/accounts/{id}/allocation?by=type\|sector\|currency` | Аллокация портфеля по измерению |
| GET  | `/accounts/{id}/value-series?months=12` | Дневной ряд стоимости портфеля и XIRR |
| GET  | `/accounts/{id}/income` | Доходный календарь: предстоящие купоны/амортизации/дивиденды |
| GET  | `/accounts/{id}/received` | Фактически полученные выплаты (с учётом позиции на дату отсечки) |
| GET  | `/accounts/{id}/tax` | Расчёт НДФЛ с учётом типа счёта и ЛДВ |

Пять эндпоинтов от `positions` до `tax` считаются из одного снапшота портфеля, но каждый строит его
заново — это отдельный прогон FIFO и отдельный обход выплат на каждый вызов. Страница счёта поэтому
ходит в `/overview`; частные эндпоинты оставлены для интеграций, которым нужен один кусок.

## Аналитика инструмента и портфеля

Финансовые расчёты вынесены в отдельные чистые классы домена (`domain/analysis`, `domain/portfolio`) —
без БД и сети, тестируются изолированно; бэкенд считает, фронт только отображает.

- **Доходности инструмента** (`ReturnsCalculator`): изменение за 1Д/1Н/1М/1Г/YTD и 52-нед. диапазон из дневных свечей.
- **Метрики облигации**: НКД и дата оферты дочитываются из MOEX (миграция `V3`); текущая доходность — производная модели `Bond`.
- **Дивидендная доходность акции** (`DividendYieldCalculator`): сумма выплат за 12 мес / цена.
- **Аллокация портфеля** (`AllocationDimension` + `AllocationDimensionFactory` + `AllocationCalculator`):
  разбивка по типу/сектору/валюте. Измерение — паттерн **Strategy**; новое измерение = новый бин (**OCP**),
  фабрика собирает их списком автоматически.
- **Позиции и P&L** (`FifoCalculator`): свёртка сделок по FIFO — открытые лоты и реализованные продажи,
  комиссии распределяются на единицу. Даты покупки/продажи сохраняются: по ним считается ЛДВ.
- **Прогноз выплат** (`IncomeForecaster`): купоны и амортизации точно по графику MOEX; дивиденды —
  только с объявленной датой отсечки. Прикидка «по прошлогодней выплате» намеренно не строится:
  для разовых выплат она вводит в заблуждение.
- **НДФЛ** (`TaxStrategy` + `AbstractTaxStrategy` + `TaxStrategyFactory`): брокерский счёт, ИИС типа А и Б —
  **Strategy** поверх **Template Method**. Прогрессия 13/15% от порога, ЛДВ при владении ≥3 лет.
  Ставки лежат в `TaxRates` — единственном источнике истины и для налога, и для оценки выплат «на руки».
- **Стоимость портфеля во времени** (`PortfolioValueCalculator` + `PortfolioValueRequest` — **Builder**):
  дневной ряд «рыночная стоимость / вложенный капитал». Сделки прокручиваются по календарю одним
  проходом — O(дней + сделок). Котировки облигаций приводятся из процентов от номинала в рубли
  (`InstrumentPricing.moneyPerUnit`).
- **Доходность XIRR** (`XirrCalculator`): метод Ньютона с откатом на бисекцию — на реальных потоках
  Ньютон расходится (производная NPV вырождается, шаг выбрасывает ставку за `r ≤ −1`), бисекция
  сходится гарантированно. В потоки входят все сделки за историю счёта, полученные выплаты
  и текущая стоимость позиций как терминальный поток.

На фронте переиспользуемые графики живут в `shared/charts` (кольцевая диаграмма аллокации,
столбцы выплат, многорядный линейный график).

## Тесты

```bash
cd backend && ./gradlew test              # 54 модульных теста, Docker не нужен (~15 c)
cd backend && ./gradlew integrationTest   # 4 теста на Testcontainers, нужен запущенный Docker
cd frontend && npm run build              # проверка типов + сборка
```

Покрыты все чистые калькуляторы домена (доходности, дивиденды, FIFO, налоги, аллокация,
прогноз выплат, ряд стоимости, XIRR), сериализация кеша и загрузка контекста приложения.

Классы `*IT` вынесены из `test` в отдельную задачу `integrationTest` и не входят в `check`:
они поднимают PostgreSQL в Testcontainers, и при выключенном Docker сборка падала бы при
полностью исправном коде. `ApplicationContextIT` поднимает полный контекст приложения —
остальные тесты модульные, и без него рассинхрон конструкторов или недостающий бин
всплывали бы только в рантайме. Redis ни там, ни там не требуется.

## Замечание по данным

У MOEX ISS нет прямого кредитного рейтинга — надёжность облигаций оценивается прокси-эвристикой
(уровень листинга + признак ОФЗ) в `ReliabilityScorer`; заменяется на реальный источник без изменения
остального кода. Аномальные доходности (YTM в сотни %) помечаются флагом `suspiciousYield` и по умолчанию
исключаются из выборок и сводок.

Котировки облигаций MOEX выражены **в процентах от номинала**, а дюрация приходит **в днях**
и в блоке `marketdata`, а не `securities`. Один выпуск отдаётся на нескольких режимах торгов —
парсер дедуплицирует по `SECID`. Везде, где облигация оценивается в рублях, цена проходит через
`InstrumentPricing.moneyPerUnit`.

**Бессрочные выпуски не попадают в выборку.** `MoexBondParser` отбрасывает бумаги без `MATDATE`
(вместе с настоящим мусором в сырых данных), а у перпетуальных облигаций даты погашения нет
по определению. Расчёты доходности и дюрации на них тоже опираются, поэтому это осознанный
компромисс, а не недосмотр: поддержка потребует отдельной ветки в анализе, а не только правки фильтра.

## Ограничения

**Аутентификации нет.** `X-Client-Id` — это UUID из localStorage браузера, а не учётная запись:
сервер принимает заголовок на веру. Изначально так было устроено анонимное избранное, но теперь
за тем же заголовком лежат счета, сделки и налоги — любой, кто знает чужой UUID, получит доступ
к этим данным. Приложение рассчитано на локальный/личный запуск; перед выкладыванием наружу
нужна настоящая аутентификация.

**Расчёты — оценочные.** Налоги считаются по упрощённой модели (прогрессия, ЛДВ, тип счёта)
и не учитывают сальдирование убытков между счетами, вычеты ИИС типа А и валютную переоценку.
Это ориентир, а не налоговая отчётность.
